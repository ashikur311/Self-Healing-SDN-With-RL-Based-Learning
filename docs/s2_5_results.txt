Design (honest + efficient): the strategies differ ONLY in which surviving path they
choose after the primary (Path A) fails, so we measure the live QoS of each survivor
(B, C) once per seed (iperf TCP + ping) under that scenario's injected conditions,
then map each strategy -> its chosen path -> that measured QoS. Every number is real.

Strategies:
  fixed_failover  pre-provisioned order -> B         (condition-blind)
  shortest_path   lowest-latency survivor -> B        (condition-blind)
  widest_path     max observed bottleneck bandwidth   (LOAD-AWARE; the strong baseline)
  random_path     seeded random survivor              (control)
  SHIELD          Resolver, sees NOISY loss (sigma=0.05) + observed bandwidth
  oracle          Resolver with GROUND-TRUTH loss     (genuine upper bound)
Recovery weights (fixed a priori): latency 0.5, capacity 1.0, loss 1.5, hops 0.1.

HARDENING (answers the peer review):
  * M2 -- added widest_path, a load-aware max-bottleneck-bandwidth router (what a
    competent TE network does). It reacts to bandwidth, so it matches SHIELD on the
    congestion scenarios; its blind spot is LOSS.
  * M2 -- new scenario loss_C_fat: loss on the FAT (high-bw) Path C, bandwidth
    nominal. widest_path still picks C (highest bw) and tanks; SHIELD's loss-aware
    objective picks B. This is where load-awareness alone is not enough.
  * M3 -- the oracle is no longer a copy of SHIELD: SHIELD sees loss with per-seed
    noise, the oracle sees ground truth. "Within 10% of oracle" now means something.

Interpretation / honesty (the defensible paper claim):
  * Against loss-blind conventional recovery (fixed-failover, shortest-path) SHIELD
    wins broadly whenever the default path is degraded.
  * Against a STRONG load-aware baseline (widest-path) SHIELD ties on pure-bandwidth
    problems -- an honest result: load-awareness alone already handles those -- but
    BEATS it when loss decorrelates from bandwidth (gray failure on a fat link),
    because SHIELD's objective is loss-aware. That combination (latency+capacity+loss)
    is the contribution, not out-routing a widest-path router on bandwidth.
  * SHIELD matches the oracle even with noisy loss telemetry: its choices are robust
    to sigma=0.05 loss-observation noise (the loss gaps here, 0 vs 15-20%, exceed the
    noise). The oracle is now an independent ground-truth computation.
