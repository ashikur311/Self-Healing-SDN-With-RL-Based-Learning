Build:
  topologies/nonstationary.py  — `NonStationarySchedule(n_days, seed)`, Mininet-free
    + deterministic. Three things drift across D days (t = day/(D-1)):
      1. WHICH survivor is degraded after the primary (A) fails:
         p(degrade B) 0.9 -> 0.1, so early days -> Path C is best, late days -> Path B
         is best. A model frozen on "prefer C" must un-learn and re-learn.
      2. FAULT-TYPE mix: link 0.8->0.3, node 0.1->0.3, flap 0.1->0.4 (churn rises).
      3. Traffic INTENSITY: rate_choices grow (top burst rate ~4 -> ~10 Mbit).
    API: day_profile(day), distribution(day), sample_scenario(day, rep) (reproducible
    in (seed,day,rep)), optimal_survivor(scenario), build_overrides(scenario) (TCLink
    bw/loss for the degraded survivor, as in S2.5), log_schedule(path).
  topologies/traffic.py  — start_mix(dur, n_bursts, rate_choices=None): the schedule
    shifts per-day traffic intensity; default [2,4,6,8] keeps prior behaviour.
  topologies/faultgen.py — FaultInjector.inject_scenario(scenario): fails the primary
    per the day's drifting fault TYPE (link -> link_down, node -> switch_down(s2),
    flap -> flap then leave down); the survivor degradation itself is applied at
    build time via build_overrides.

Why: the learner (S3.2) only matters if the world drifts; a stationary world is
solved by a frozen model. This makes the OPTIMAL recovery path change over time and
supplies the exploratory, drifting experience the bandit learner needs -- the premise
of the S3.4 learning curve (SHIELD-online vs a frozen model).
