Abstract
Software-Defined Networking confirmed centralized, programmable management to boost
operational productivity. However, rely on a single controller increases the similiar of
errors and system outcomes. So, to resolve this challenge, we are presenting a
reinforcement learning (RL)- based self- repairing framework that autonomously
identifies, analyzes, and recovers from network failures in real time. By continu-
ously monitoring network states, the proposed system learns adaptive recovery strategies
through environmental interactions and reconfigure routing to minimize service disruption
dynamically. Stimulations on SDN topologies confirm that the proposed approach enables
quicker fault detection and recovery, lower packet loss and enhances network availability
compared to
standard rule-based recovery strategies. These result highlight the learning-based fault
management to enhance SDN resilience, expandability and operational autonomy.

Problem Statement
Static backups or manual reconfiguration are common in SDN fault-handling methods.
Because they are often too slow and rigid for large, changing networks. This project aims
to solve how SDNs can automatically and efficiently detect and recover from different
faults (like link failures, node failures, and congestion) using reinforcement learning, while
reducing downtime and packet loss.
1.2 Motivation
Modern networks such as cloud, IoT, 5G demand high availability and impetuous confor-
mation to errors. Manual troubleshooting and static recovery strategies fail to accommo-
date the size and inconstancy of current networks. Reinforcement learning paves the way
for significant advancements as like (I) Learning optimal decisions from interactions with
the network environment (II) Adapt to previously unseen failure conditions.(III) Enhance
long-term performances for instance, minimize packet loss or recovery latency. An RL-
driven self-healing SDN can minimize operational expenditures not just that, it can boost
service robustness and enhance resilience for mission-critical applications even more.
1.3 Objectives
The objectives of this project are:
1. Create an RL-based system that works with an SDN controller to automatically
detect, find, and fix network faults.
2. Build a prototype in an SDN test setup, such as Mininet with OpenDaylight or
ONOS.
3. Simulate different network problems like link failure, controller failure, and conges-
tion. Train the RL agent to fix them by actions like rerouting or updating flow
tables.
4. Test the system against basic methods using measures like detection time, recovery
time, packet loss, throughput, and controller load.
5. Check how well the system works on larger networks and new type of failures.

A concise summary of the methodology:
• Literature Review: Survey SDN fault management and RL applications.
• Testbed Setup: Create a simulated SDN environment by using Mininet (create

2.1 Preliminaries
Software Defined Networks (SDNs) separate the control plane from the data plane, allow-
ing for centralized control and flexible programmability of network behavior. The archi-
tecture of SDNs offers improved network efficiency for managing traffic, recovering faults,
and automating network behavior when compared to traditional static networks. Central-
ized network intelligence enables SDNs to dynamically configure and adapt to changing
network conditions.
2.2 Literature Review
[1] Bous Saoud et al. (2024) focused and worked on intelligent congestion detection and
traffic control in SDNs through data-driven reinforcement learning (RL) agents. Bous
Saoud’s research and study utilized Mininet and Ryu controllers for the testing of their
work and demonstrated high performance in congestion classification. Results showed
improved quality of service (QoS), precision greater than 0.91, and recall greater than
0.97 when compared to standard methods.
[2] Huang et al. (2025) proposed a Distributed Double Deep Q-Network (DDPG)-based
Link Backup Path (DDPG-LBBP) solution for fast faulty link recovery in SDN-based
Wide Area Monitoring Systems (WAMS) for smart grids. Huang’s approach resulted
in a 12.26% reduction in recovery time and a 15.31% reduction in packet loss in IEEE
test topologies. The authors recommended developing multi-fault recovery schemes and
incorporating real-time fault detection mechanisms into their future work.

3.1 Methodology and Implementation
3.1.1 Context Diagram
The context diagram represents overall connection interaction between systems component

3.1.2 System Architecture
The proposed self-healing Software-Defined Networking (SDN) framework is divided into
a multi-agent architecture. The system decouples the extraction of network state from the
intelligent decision-making process.
Agent 1 (State Identification Unit): Operating as an application on top of the
Ryu OpenFlow controller, this unit continuously polls the Mininet data plane to extract
raw port statistics and compute normalized network telemetry.
Agent 2 (Decision Unit): This unit utilizes a Proximal Policy Optimization (PPO)
Reinforcement Learning (RL) model. It ingests the telemetry from Agent 1 to autonomously
classify the network state and determine the optimal mitigation strategy (e.g., maintaining
the current path or initiating a traffic reroute).
3.1.3 Testbed Environment
To safely simulate an enterprise network environment, a virtualized testbed was con-
structed. The data plane is emulated using Mininet, utilizing Open vSwitch (OVS) in-
stances configured with the OpenFlow 1.3 protocol. The control plane is governed by the
Ryu SDN controller running in a Python virtual environment on an Ubuntu Linux ma-
chine. A linear switch topology was selected to prevent broadcast storms while allowing
for the evaluation of multi-hop traffic rerouting.

3.1.5 Detailed Methodology and Design
The proposed self-healing mechanism integrates a multi-agent Reinforcement Learning
(RL) framework within the SDN controller. The design follows a continuous closed-loop
operational pipeline:
1. Network State Monitoring: The controller actively gathers raw data plane statis-
tics, including byte counts, packet drops, and control-plane latency.
2. State Normalization: The raw data is mathematically normalized into standard-
ized metrics (Throughput, Packet Loss Rate, and Delay).
3. RL Decision Agent: A Proximal Policy Optimization (PPO) model evaluates the
normalized state array and selects the optimal recovery strategy.
4. Policy Update: The RL agent refines its recovery strategy by observing the net-
work’s subsequent performance after each action is taken.
5. Autonomous Recovery: The controller translates the agent’s selected action into
dynamic OpenFlow protocols to update the network path autonomously.
3.4.1 State Identification Logic (Agent 1)
To achieve the monitoring and normalization phases, the SDN controller utilizes a custom
polling script. The controller queries the OpenFlow switches every 3 seconds to pull OF-
PPortStatsReply messages. The raw byte difference is converted into kilobits per second
(kbps), and the values are scaled between 0.0 and 1.0 to optimize neural network gradient
calculations.

4.1 Environment Setup
A fully virtualized testing platform was created to safely mimic a corporate network and
execute the proposed algorithms. The configuration was executed on an Ubuntu virtual
machine running via VirtualBox.
• Data plane: Mininet was utilized to simulate the core network framework, featuring

multi-hop routing experiments.
• Control plane: The Ryu SDN platform was set up in a dedicated Python 3.9

identification element (Agent 1).
• Machine learning framework: The decision component (Agent 2) was created

(PPO) algorithm to develop and enhance control policies.

4.2.2 Overcoming Dataset Class Imbalance
In the initial training stage, the decision unit faced a class imbalance problem. As the
network functioned normally for the majority of the simulation time, the dataset showed a
notably uneven distribution between typical traffic occurrences and severe fault situations.
Consequently, the reinforcement learning agent developed a skewed strategy, consistently
opting for the “Do Nothing” action to optimize baseline rewards.
To address this issue, an oversampling technique was applied using the pandas library
prior to training. The minority class (fault-related data) was duplicated until its size
matched that of the majority class (healthy-state data). This adjustment ensured that
the PPO algorithm focused on meaningful telemetry patterns rather than relying on biased
statistical distributions.
4.2.3 The “Zero-Packet” Logic Edge Case
A significant edge case occurred during complete physical link failures. When a link is
entirely disconnected, packet transmission stops completely, resulting in a total packet
count of zero. Standard packet loss calculations based on percentage of total packets sent
can therefore lead to a division-by-zero error. If this scenario is handled by assigning a
default value of zero, the failed link would incorrectly indicate 0% packet loss.
To prevent this misinterpretation, custom logic was implemented in the live controller.
Any active port reporting 0.0 Kbps throughput was directly interpreted as experiencing
100% packet loss. This ensured that the reinforcement learning agent could accurately
detect and respond to actual physical link failures.
4.3 Results and Discussion
4.3.1 Network State Monitoring
The Ryu-based state identification module efficiently monitored degradation in the data
plane in real time. When the fault injection script was triggered, telemetry data immedi-
ately reflected a sharp drop in throughput to 0.0 Kbps, accompanied by a simultaneous
spike in packet loss reaching 100%.
4.3.2 Autonomous Decision Testing
The trained model followed deterministic outcomes typical of discrete network environ-
ments. The agent correctly identified that minor increases in latency did not require
corrective action and initiated recovery only during genuine link failures.

Chapter 6
Conclusion
The objective for this phase of the Final Year Design Project has been successfully com-
pleted. The results demonstrated that separating network state monitoring from routing
decisions through a multi-agent design is feasible and viable. The combination of collect-
ing OpenFlow telemetry data and implementing a Proximal Policy Optimization (PPO)
model-based reinforcement learning model allowed the system to identify the scenarios and
physical link failures autonomously. Through the testing process, the agent successfully
identified the normal conditions versus actual faults that provided reliable autonomous
operation without requiring operator input.
6.1 Summary
Although detection and decision-making were the primary focus of FYDP 2, the next
phase will focus on implementing these decisions directly within the network. Proposed
improvements include extending the controller logic to translate the agent’s rerouting
decisions into OpenFlow (OFPFlowMod) messages. This would allow the controller to
immediately update the switch flow table, thereby allowing traffic to be redirected through
alternative paths in the case of a failure. It is expected that this enhancement will bring
the system much closer to being a fully autonomous, zero-touch, self-healing system.
6.2 Limitation
Although this project gives good results using a virtual network by using Mininet and
RYU SDN controller, this virtual setup did not determine the full complexity of a large-
scale network. A real network may be more complex to predict. The RL model trained
with minimal parameters can detect and handle one or two problems, like link failure or
rerouting. It may take longer to compute when trained on large-scale real-world datasets,
which could impact the ability of the system to quickly adapt to changing environments.
Thus, it is necessary to improve the boundaries mentioned above.
