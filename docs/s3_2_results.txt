S3.2 — Learner loop (re-fit Resolver from experience)             PASS
================================================================================
Build:  framework/agents/learner.py  (stdlib only, like the store)
  What is learned: the Resolver scores a path by w.goodness(path) (per-dim min-max
  goodness of latency/capacity/loss/hops within the candidate set). The learner
  estimates, per dimension, the covariance between a chosen path's goodness in that
  dimension and its realized reward, clips at 0, scales to mean-weight 1, and sets
  the Resolver's weights to that. Intuition: up-weight the path-features that have
  historically predicted good recoveries -> the framework DISCOVERS the objective
  instead of us hand-setting it (in the demo, capacity/loss emerge as the drivers,
  matching the S2.5 hand-tuned recovery weights).

  Forgetting guard: split a VALIDATION slice BEFORE fitting (val_fraction=0.3,
  deterministic seeded shuffle); accept the new weights only if held-out fit quality
  (Pearson corr between w.goodness(chosen) and reward) does not drop
  (>= val_before - 1e-6); otherwise keep the old weights.

  Bandit honesty: feedback is bandit (only the installed path's outcome is seen), so
  this is an off-policy, correlational estimate that needs EXPLORATORY experience to
  learn -- exploration is introduced by S3.3's non-stationary schedule. On purely
  on-policy data the guard correctly REJECTS (verified during bring-up).

  API: Learner(resolver, val_fraction).update(records, seed) -> report
  {train_n, val_n, old_weights, new_weights, val_before, val_after, accepted, reason};
  update_from_store(store, seed). Records must carry candidate QoS
  (path+latency/capacity/loss/hops), which Resolver.select()['ranked'] already emits.
