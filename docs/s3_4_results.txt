Setup (honest): the world drifts (topologies.nonstationary) so the LOSS lands on
Path B early (Path C best) and on Path C late (Path B best). Degradation is LOSS
ONLY -- bandwidth stays nominal -- and loss is the signal the thesis established is
NOT observable at decision time (gray failure). So the recovery agent cannot read
the right path from telemetry; it must LEARN which path currently pays off from
realized rewards and RE-learn when the world flips. THREE agents share the day-0
Resolver (capacity-favouring INIT_WEIGHTS -> all start correctly picking Path C):
  * SHIELD-online: records each recovery and re-fits the Resolver each "day" on a
    2-day recent window (framework/agents/learner.Learner); epsilon-greedy(0.25).
  * frozen: same day-0 Resolver, never updates (the do-nothing ablation).
  * adaptive (p3-review M4): a principled ADAPTIVE NON-LEARNING baseline -- a
    sliding-window-greedy non-stationary bandit that tracks each survivor's mean
    reward over the last 2 days and greedily picks the better arm (eps-greedy). This
    is the honest bar: SHIELD-online must at least MATCH a competitor that also
    adapts to drift, not merely beat a model that is frozen by construction.
D=9 days, 8 seeds (p3-review M3: was 5 -> real margin below 0.05), 16 recoveries/day.

QoS provenance: a QoS table QoS[path][healthy|lossy] is MEASURED LIVE on the mesh
(iperf TCP + ping, S2.5 harness, loss=15% on the degraded survivor, bandwidth
nominal). This run measured:
    B@healthy 10.6+/-0.4 Mb (0%)   B@lossy 0.2 Mb (23%)
    C@healthy 17.0+/-1.8 Mb (0%)   C@lossy 1.8 Mb (30%)
The D-day loop draws each recovery's outcome from that measured table (mean+/-std),
so every QoS number traces to a live measurement while the many-day/seed replication
needed for a p-value is trace-driven. (A fully-live D-day loop remains future work.)

Interpretation / honesty:
  * This is the project's NOVELTY: on a non-stationary world SHIELD updates itself
    day-by-day and adapts; a frozen model of the same objective decays. "Improvement
    day1->D" is realized as the online-vs-frozen advantage that opens up as the world
    drifts (0 at day 0 -> +15.8 by day 8), which the frozen ablation cannot achieve.
  * The hardened bar (M4) shows SHIELD-online is not just beating a strawman frozen
    model -- it MATCHES a genuine adaptive competitor (sliding-window-greedy bandit)
    while doing so through interpretable Resolver-weight updates rather than a raw
    arm table. The contribution is a self-updating framework, not a new bandit.
  * Learning is only necessary BECAUSE loss is unobservable at decision time; with
    full telemetry the S2.5 heuristic already suffices (that is why the framework, not
    RL, was the Phase-2 contribution). Here the value is ADAPTATION under partial
    observability + drift.
  * Trace-driven with live-measured anchors; a fully-live D-day loop is future work.
